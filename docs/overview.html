OddsDrift & the Attention Engine

A machine that builds an audience without a human in the loop. The engine (attention) is generic — pluggable data sources, post shapes, and publishing channels. OddsDrift is its first audience: an automated tracker of prediction-market odds that posts three times a day to Bluesky, the fediverse, Nostr, and its own site with RSS.

Why this shape

The constraint was total autonomy: no phone number, no CAPTCHA, no card, no logins. That ruled out the obvious channels — X needs a phone and a paid API, Bluesky's own signup needs phone or CAPTCHA, every sizeable community PDS is invite-gated, and Mastodon.social forbids AI-only accounts. The research (12 agents, live-verified) surfaced the one path that needs zero accounts: Bridgy Fed's web-site bridge turns any site with the right markup into a followable Bluesky and fediverse account with one HTTP request. Add Nostr (a keypair, no signup), a site with feeds, and GitHub Actions as the only free scheduler, and the whole loop runs from public infrastructure.

The topic won a judged bake-off (three strategists, three judges): prediction-market odds are public, keyless, change hourly, are quotable, and no bot covers them well. Content is deterministic — templates plus arithmetic on data — so it stays honest without an LLM.

How it works

  1. Fetch. ~80k open Kalshi markets (parlay legs excluded) and the top ~2,100 Polymarket markets by 24h volume, plus everything that settled in the last 26h. Watchlist markets below the volume cutoffs are fetched by ticker/slug.
  2. Enrich. 24h change comes from the engine's own snapshot taken ~24h earlier; the venue-reported change is only a fallback. Prices 24h before settlement come from snapshots or from the venues' history endpoints.
  3. Shape. The due slot's shape picks rows by threshold, ranks them, writes ≤ 280 characters of templated text, and renders a 1200×675 chart with alt text.
  4. Publish. The post page carries microformats2 (h-entry, e-content, u-photo, a link to fed.brid.gy). Bridgy accepts the webmention, then the engine verifies delivery through Bridgy's convert endpoint before it marks the post done. Nostr notes use a stable created_at so re-runs never duplicate.
  5. Remember. The git repo is the storage of record: slim per-run snapshots, a resolutions ledger, the post index, publish records, daily metrics. Slots are idempotent; a transient failure leaves the slot open for the :47 retry tick.

Guardrails

  • Honest by construction. No LLM writes copy. Every number is computed from the APIs and linked to the venue's market page and to a page with the full table. Bot disclosure sits on every surface; the bot never replies, follows, likes, or mentions.
  • Fails loudly, not silently. Schema drift or a dead source blocks the post; breakers open after three failed runs and half-open after a cooldown; the healthcheck watches post freshness, not just "did the job run".
  • Small footprint. Free tiers only: GitHub Actions minutes, Cloudflare Workers Free (10 ms CPU — the Worker just serves KV), KV under 100 writes/day, snapshots trimmed to seven columns and non-sports rows.
  • Reviewed. A 45-agent adversarial review (five reviewers, one refuter per finding) confirmed 35 defects before launch — including one that would have frozen the site within a week — all fixed and re-verified with 60 tests, a Worker typecheck, and live runs.

Reusing it for the next audience

Everything audience-specific lives in one folder. The engine never mentions OddsDrift.

audiences/<name>/audience.yml   # names, domain, sources, shapes + UTC times, channels, thresholds, links
audiences/<name>/about.md       # method page
audiences/<name>/assets/        # avatar.png, header.png
audiences/<name>/wrangler.jsonc # its Worker (domain, KV id, vars)
engine/sources/  engine/shapes/  engine/channels/   # add a module + register it to add a source, post type, or platform
  1. Copy audiences/oddsdrift/, edit audience.yml (topic sources, post shapes, times, channels, domain), swap the assets.
  2. Add the new slot times to the cron list in publish.yml (the workflow warns when a slot has no matching cron entry).
  3. Create a KV namespace, set SYNC_TOKEN, wrangler deploy the site to its domain.
  4. Enable the bridge: curl -X POST -d "url=<domain>" https://fed.brid.gy/web-site — then run the workflow once. New platforms are one channel module each; a Mastodon channel and an API signup helper (tools/mastodon.mjs, email via AgentMail) already exist, switched off.
